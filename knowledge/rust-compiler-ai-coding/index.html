바이브 코딩 시대, 왜 Rust가 떠올랐을까?

트렌드가 바뀌며 Rust가 떠올랐다. 바이브 코딩(AI가 쓴 코드를 거의 읽지 않고 그대로 쓰는 방식)으로 코드가 쏟아져 나오지만, 모두 제대로 돌지는 않는다. 그만큼 에러와 시행착오가 늘고, 그 비용도 커진다. 꼭 돈이 아니더라도 말이다.

마지막 '완성' 버튼(컴파일)을 누르면 Rust는 깐깐하게 에러를 검사한다. 그래서 이 비용을 아끼고, 에러를 미리 막는다.

자동화 라인으로 보면

수작업 공장에서는 만들면서 일정 부분 검수도 함께 했다. 자동화 라인으로 바뀌자 제품은 쏟아져 나오는데, 그 작은 검수가 빠지면서 불량이 새 문제로 떠올랐다. 부랴부랴 라인 뒤편에 검수 인원을 두어도, 쏟아지는 물량이 워낙 많아 다 보기 어렵다.

Rust는 라인 끝단에 강력한 자동 검수 모듈을 단 언어다. 그래서 이 문제를 미리 막는다.

출처: 바이브 코딩은 Andrej Karpathy가 2025년 2월에 붙인 이름이다. DORA 2024 보고서는 AI 도입이 늘수록 배포 안정성(배포 직후 손봐야 하는 비율 등)이 7.2% 떨어진 것으로 추정했다.

단계마다 한 줄

  1. 쓰기(생산)예제는 AI가 흔한 경우만 맞추고 드문 경우(목록에 없는 이름, 짧은 단어 둘이 이어진 목록)를 놓친 코드다.
  2. 검사(라인 끝 자동 검수)Python은 문법만 보고 바로 실행한다. Rust는 타입과 빌림 규칙까지 보고, 어기면 실행 파일을 만들지 않는다. 빌림 규칙은 값을 고치라고 빌려준 동안 다른 곳이 그 값을 빌리지 못하게 하는 규칙이다.
  3. 테스트와 실제 입력(뒤편 검수와 출하)Python에서는 두 예제 모두 테스트를 통과하고, 실제 입력에서야 불량이 드러난다. ①은 에러로 멈추고, ②는 에러 없이 틀린 답을 낸다.
  4. 고치기(라인으로 되돌리기)rustc는 몇째 줄이 왜 안 되는지 적고, 두 예제에는 고칠 방법(help)도 붙였다. 이 에러를 AI에게 돌려주면 다음 판을 쓸 수 있다. 2023년 한 연구에서는 GPT-4가 이렇게 되풀이해, 인기 Rust 라이브러리의 실제 GitHub 커밋 182개 가운데 134개를 다시 컴파일되게 고쳤다.

출처: 반복 방식은 Deligiannis 외(2023) 2.2절, 커밋 134/182(73.63%)는 표 3의 GPT-4 결과(답 다섯 개 중 고름, N = 5)다. 커밋은 crates.io 상위 100개 라이브러리의 GitHub 기록에서 찾은 것이다.

자주 묻는 질문

바이브 코딩이란?

AI에게 말로 시키고, 나온 코드를 거의 읽지 않고 그대로 쓰는 방식이다. Andrej Karpathy가 2025년 2월 X에 처음 쓴 이름으로, 코드가 있다는 것조차 잊고 AI의 변경을 모두 받아들이는 코딩을 가리켰다.

AI로 코드를 쓰면 정말 에러가 느나?

DORA 2024 보고서(Google Cloud)는 AI 도입이 늘수록 배포 처리량이 1.5%, 배포 안정성이 7.2% 떨어진 것으로 추정했다. 안정성은 배포 직후 손봐야 하는 배포의 비율 같은 지표로 잰다. 설문에 바탕을 둔 추정이다.

Rust는 왜 AI 코딩에 잘 맞나?

Rust 컴파일러는 타입과 빌림 규칙을 실행 전에 검사하고, 어기면 줄 번호와 이유를 적은 에러를 낸다. 이 글의 두 예제에서 rustc 1.100.0은 두 실수를 모두 실행 전에 거부하고 고칠 방법(help)도 붙였다. Python 3.11.4에서는 같은 실수가 테스트를 지나 실제 입력에서야 드러났다.

AI가 컴파일 에러를 받아 고치는 방법이 실제로 통하나?

Microsoft Research의 RustAssistant(2023)는 컴파일러의 에러를 코드와 함께 LLM에 주고, 고친 뒤 다시 컴파일하기를 되풀이했다. GPT-4로, 인기 Rust 라이브러리 100개의 GitHub 기록에서 찾은 컴파일 에러 커밋 182개 가운데 134개(73.63%)를 다시 컴파일되게 고쳤다. 2023년 모델의 결과다.

Python으로는 같은 실수를 미리 잡을 수 없나?

Python은 기본으로 문법만 보고 실행한다. 타입 검사기 mypy는 None일 수 있는 값을 확인 없이 쓰는 것을 막지만, 타입 힌트를 단 함수만 검사한다(mypy 문서). 이 글의 Python 예제처럼 힌트가 없으면 기본으로는 검사하지 않는다.

Rust 컴파일러가 잡지 못하는 실수는?

타입과 빌림 규칙에 어긋나지 않는 실수다. Rust 책은 타입 시스템이 모든 것을 잡지는 못한다며, 2를 더해야 할 함수가 10을 더하는 경우를 예로 든다. 이런 논리 오류는 테스트가 잡아야 한다.
