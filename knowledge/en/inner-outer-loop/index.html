When you automate the outer loop, what stops AI slop?

AI agents already do the coding. If a bot now also gathers the requests and bug reports and decides what to work on, what takes in the flood of work? Here is the answer of Lauren Tan, who builds Grok Bot at SpaceXSI.

Automate the outer loop and the incoming work explodes. What takes that work in without slop is a solid inner loop, above all the codebase.

Lauren Tan's argument in seven steps

  1. 1

    The outer loop, before. Through windows such as Slack, Linear, X, and email, a person sorted the requests and bug reports and decided what to build.

  2. 2

    The inner loop, before. As AI agents such as Codex or Claude Code took over the coding of what was decided, productivity went up.

  3. 3

    Now Grok Bot can automate the outer loop. Then the outer loop's throughput explodes.

  4. 4

    The small slop the old inner loop produced grows as much as the input does. This is where the AI slop problem comes from.

  5. 5

    So a solid inner loop is needed. Tan offers four axes. The most important is the codebase, then static analysis, verification (above all, agents running the code themselves), and prose.

  6. 6

    These days people focus on prose, but the most important is the codebase. Press an axis in the figure above to see its example.

  7. 7

    A solid inner loop built this way takes in all of the outer loop's exploding throughput. Slop, bye bye~ (not quite bye).

The numbers in the figure are a simplified example, and so are the size ratios of the four boxes. With no axis, the AI slop rate is set to 10%; the codebase cuts it to a quarter, static analysis and verification each to a half, and prose to four fifths. The 10 a day a person can gather and sort is a set value too.

Frequently asked questions

What are the inner loop and the outer loop in AI coding?

In Lauren Tan's words, the inner loop is AI agents fixing and checking code toward your intent, and the outer loop is everything off the codebase: the bug reports and requests that come in through Slack, Linear, and X. Tan calls Cursor projects the inner loop and Grok Bot the outer loop.

What is AI slop?

A word for sloppy output made by AI, here sloppy code. In the AI Engineer CODE 2026 talk, Lauren Tan said that if your inner loop produces slop, automating that loop just produces more slop.

How does Grok Bot automate the outer loop?

The bot watches a Slack channel; when a bug report comes in, it first reproduces the bug, and if it is still on the latest main, it hands it to a Cursor project as a task. The bot takes over the relay in which a person read the reports and passed them to the agents (Matt Pocock livestream, 2026-10-02).

What are the four axes that make the inner loop solid?

Tan draws where to spend time in this order: codebase, static analysis, verification, prose. The first two are checks done in code, so they give the same result every time; verification is runtime and formal verification; prose is text that needs judgment, such as rules, skills, and agents.md.

Why does the codebase matter more than rules like agents.md?

Tan says that whenever you correct your agent, turn it into a deterministic check instead of adding another line to your rules, because code is far more reproducible. For example, banning React's useEffect in product code and allowing it only in some places inside the APIs of Dune, the team's own framework, made that whole class of mistakes disappear.

Do AI agents merge their own pull requests?

Lauren Tan says that once there is nothing left to review, you can let agents merge most of their own pull requests, and that Tan's code review has shrunk to looking at verification artifacts. Tan's team shipped about 11,000 pull requests last month, with a revert rate steady at about 0.5%. These are figures Tan gave in the talk.
